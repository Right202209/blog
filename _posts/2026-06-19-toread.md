# 校招季我的简历到底该怎么写

> 作者：tomczhang  
﹥ from [Linux.do](https://linux.do/t/topic/2435203)
> 2026-06-19

前两天发了一篇招暑期实习生的帖子《[暑期实习]坐标阿里，招几个暑期实习生的师弟》，主要是给我自己找个师弟，顺带着帮佬们改改简历。到目前为止已经给 20 多位佬的简历提供了意见。

我发现大家的问题都是共性的。所以我在想，也许我可以写一篇教大家怎么写简历的文章，以及怎么样准备自己面试的文章。有时候啊，很多的问题，大家不是不知道，只是就像窗户纸一样，没有人给你捅开。一通百通，那我就来做这个点开窗户纸的人好了。

---

## 面试官想招什么样的人？

核心就三点：**技术基础扎实、技术能力强、技术热情高**的候选人。分开来讲：

- **技术基础**：就是简历的技术栈里边，有没有写一些并发处理、分布式锁、trade-off 的内容，而不是罗列技术栈，例如“熟悉 Spring boot、熟悉 JVM”。
- **技术能力**：项目是 CRUD 还是有难点、亮点，是电商网站类项目还是更有趣或者有难度的复杂项目。例如：逆向过一个没有开放的 API，写过一个自己、身边人一直在用的小应用，用 AI 复刻过一个应用中特别经典的功能。这些东西都是能体现你的想法的，如果没有什么有价值/难度的项目，写一个这个会很加分。
- **技术热情**：有一些别人没有的东西，例如给高 Star 的 GitHub 提 PR，自己有很多有意思的小项目（每个都写好 README，精美的成果截图，一看就很用心），有自己的技术博客（内容扎实，常年维护）。

## 我的简历中到底要应该写什么样的内容？

这个问题可以转换一下问法：**面试官到底关心简历中什么样的内容？** 毫无疑问，面试官关心能佐证上面三点的内容。审视一下自己的简历，简历里所有的内容都应该围绕着这三点来写。不涉及到这三点的，全部都可以删除。

按照重要程度从高往低排，分别是：

| 等级 | 内容 |
|------|------|
| **S** | 好学校、中大厂的实习履历 |
| **S-** | 高规格的奖（典型的：国家奖学金、ACM 竞赛）、高质量论文 |
| **A** | 优秀项目成果、优秀项目方案、有价值的 GitHub 地址、有价值的博客地址 |
| **B** | 简历中技术栈的表达、简历排版 |
| **C** | 热情洋溢的又不失端庄的头像、丰富的社团活动 |
| **没用** | 流水账罗列技术栈、不重要的奖项、不到前 5% 的绩点 |
| **倒扣分** | 与岗位无关的实习经历、项目经历，无独特见解的 Vibe Coding 声明，无重点的表达，丑头像，简历长度超出 1 页 |

面试官当打开你的简历的时候，很有可能只给你的简历 10 秒钟，你需要在 10 秒钟之内抓住他。长篇大论没有意义，要把最重要的东西写在最重要的地方。

为什么好学校和中大厂最重要？因为这是能佐证候选者优秀、聪明、努力的直接证据，相当于候选人已经被学校和其他公司验证过了。项目成果和方案、GitHub 和博客，是佐证候选人的间接证据，没被验证过的。简历中的表达、排版、头像，代表候选人的重视程度和认真程度。

尽管这么说不是很负责任，但是实际情况就是，如果你在简历的右上角贴一个一眼看过去就丑丑的、很邋遢的头像，你的简历马上就被毙掉了。

> 人丑不要外扬，默默的藏起来，等拿到 offer 公司就拿你没办法了。

## 怎么样使我的项目经历让人眼前一亮？

上面我们已经说过，第一印象非常的重要。所以我们的核心就是要让简历在第一眼就能抓住别人眼球。越是 S 和 A 级内容瘸腿的同学，越应该做好这件事，主打一个“简历不快也光”。

但是往往越是优秀的同学，简历越是干净清爽，排版舒服。越是差的简历，越是啰啰嗦嗦一大堆，甚至写好几页。

简历排版具体怎么排？其实没有一定之规，但一定有几个特点：

- 标题清晰，和内容有区分度
- 重点清晰：有粗体、有标准体、有较小字体
- 优先级清晰：自己最独特最重要的事情在简历中最醒目的位置

## 日常准备，我能做什么？

台上一分钟，台下十年功。面试的功夫其实都在日常。那日常准备我能做些什么呢？

首先需要明确目标，即到底要往哪个方向准备。如果让你用一个词来描述一下面试准备的方向，你觉得应该是什么呢？

我觉得是 **影响力**。日常的一切努力都应该是向影响力靠近，用影响力来评估。好的成果是影响力，好的 GitHub 项目也是影响力，博客是影响力，团队、社团活动是影响力。好学校和好公司是影响力强的结果。

所以，有影响力的事情就多做，没有影响力的事情就少做、不做。这样我们的准备就会越来越充分。

## 如何权衡 Vibe Coding 和八股文？

Vibe Coding 的护城河很低，除非你搞出了一个类 Raft 的多 Agent 协作，或者是 Hands-off 复刻一个 APP 的自动化流程，那我觉得可以讲一下。

就怕每月消耗 token 不超过 200 刀，甚至没有用 cc usage 这种东西统计过自己的 token 消耗量，还在一个很简单的 chat - modify - 人 check 的流程里，那就很拉。讲出来一定是减分项。

Vibe Coding 这东西，就好像骑自行车，假设都不浪费，一个用了 20 亿 Token 的人就是比只用了 20M 的人厉害。

**八股文是基础**，是只靠学习和背就能拿下来的护城河，而且会收益一辈子。年轻的时候飘着，这一辈子都飘着，沉不下来的。八股文之所以重要，就是因为这就是日常工作中最容易出现、最经常解决的问题。

没有八股，出了问题，AI 解决不了，都不知道怎么修。只能像个憨憨一样，PUA AI，祈祷式编程，乞求它能改好。这种无力感，我相信你不想体验。

当然了，学习八股要讲究方式方法。用 AI 来学习八股，把 AI 当成自己的老师、小黄鸭、考官，学起来事半功倍。

## 我明年就毕业了/非 985，时间不够/学校不好怎么办？

朝闻道，夕死可矣。有些事情努力一周就有结果，有些事情努力一年才有结果。只要努力，就已经朝着结果前进了。

不管是大学还是公司，都是人生道路上的一个阶段，自己的成长才是永恒的，贯穿人生始终的。时间不够，学校不好，那是历史原因导致的，没有办法改变了。

我们能改变的就是只有当下。当下多进一分，就前进一分，多进两分，未来就能补足一分。化历史的不足为力量，而不是沉浸在过去的缺憾里。
